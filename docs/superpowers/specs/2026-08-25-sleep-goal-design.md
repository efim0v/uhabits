# Цель по сну — дизайн

**Статус:** утверждён 25 августа 2026
**Тип работы:** расширение, не перенос. Прообраза в Kotlin нет.

## 1. Что строим

Новый вид цели: сложная суточная цель по сну с тремя составляющими — время отхода ко сну, время подъёма и фактическая длительность сна. Данные берутся из Apple Health (Apple Watch), при их отсутствии вводятся вручную. Каждая ночь оценивается процентом выполнения по нелинейной модели.

Это первый шаг к более общей теме «трекинг времени, а не только факта». Сон выбран первым, потому что у него есть надёжный автоматический источник данных.

- Правило «ядро не импортирует `package:flutter` и `dart:ui`» действует на новый код без исключений.

## 3. Модель данных

### 3.1 Как распознаётся привычка со сном

**Третий элемент в `HabitType` не заводится.** Паритетное правило `models.habit-type-enums#1` гласит, что перечисление имеет ровно два элемента, и оно закрыто тестами. Добавление третьего потребовало бы переписать паритетные тесты так, чтобы они утверждали не то, что написано в реестре, — и реестр из механически истинного стал бы наполовину декоративным.

Привычка со сном — это **числовая привычка, у которой есть цель сна**. Признак один: наличие строки в `SleepGoals`. Без цели это обычная числовая привычка, и ничто в приложении не ведёт себя иначе.

Следствия: `habits.type` остаётся равным 1, поэтому база по-прежнему читается оригиналом; CSV-экспорт остаётся побайтово паритетным; ни один паритетный тест не затрагивается.

Создание привычки со сном фиксирует следующие параметры, которые затем нельзя переопределить в редакторе:

| Параметр | Значение |
|---|---|
| `type` | `numerical` |
| `numericalHabitType` | `atLeast` |
| `targetValue` | `100` |
| `frequency` | `1/1` (ежедневно) |
| единица измерения | `%` |

### 3.2 Значение записи дня

`Entry.value` = процент выполнения × 1000, диапазон 0…100000.

Это соглашение существующего кода для числовых привычек (величина × 1000), поэтому расчёт оценки, серий, календаря, графиков и виджетов работает **без единой правки**. Проверено по коду:

- `ScoreList.recompute` при знаменателе 1 даёт `min(1, value / 1000 / targetValue)` — для 87000 это ровно 0.87.
- День без записи приходит как `Entry.unknown` (−1), превращается в `max(0, −1) = 0` и обновляет оценку нулём.
- День с `Entry.skip` пропускает обновление оценки, значение переносится с предыдущего дня.
- `EntryList.countSkippedDays` уже умеет считать пропуски за период.

**Служебные значения.** 1, 2 и 3 зарезервированы под `yesAuto`, `yesManual` и `skip`. Геометрическое среднее способно дать 0.003% и попасть ровно в 3, что молча превратит день в пропуск. Поэтому: посчитанное значение в диапазоне 1…3 приводится к 0. Значение выше 100000 обрезается до 100000.

### 3.3 Таблица ночей

```sql
create table SleepSessions (
    id integer primary key autoincrement,
    habit integer not null,
    day integer not null,              -- логический день (день пробуждения), daysSince2000
    bed_start integer not null,        -- UTC, миллисекунды
    wake_end integer not null,         -- UTC, миллисекунды
    asleep_minutes integer not null,   -- фактический сон внутри эпизода
    derived_from_asleep integer not null,  -- 1, если границ «в постели» не было
    utc_offset integer not null,       -- минуты, действовавшие в момент пробуждения
    source integer not null,           -- 0 health, 1 вручную
    source_id text,                    -- bundle id источника в Health
    updated_at integer not null
);
create unique index idx_sleep_sessions_habit_day on SleepSessions(habit, day);
```

Одна строка на ночь. Сырые отрезки не хранятся: они всегда доступны повторным запросом к Health, а хранение дублей усложняет пересчёт.

### 3.4 Таблица целей

```sql
create table SleepGoals (
    habit integer primary key,
    bed_minutes integer not null,              -- цель отхода, минут от полуночи
    wake_minutes integer not null,             -- цель подъёма, минут от полуночи
    min_sleep_minutes integer not null,        -- по умолчанию 450 (7:30)
    weight_sleep real not null,             -- по умолчанию 0.4
    weight_bed real not null,                  -- по умолчанию 0.3
    weight_wake real not null,                 -- по умолчанию 0.3
    half_credit_time_minutes integer not null, -- по умолчанию 90
    half_credit_sleep_minutes integer not null,-- по умолчанию 60
    home_utc_offset integer not null,          -- минуты
    adaptation_minutes_per_day integer not null,-- по умолчанию 60
    merge_gap_minutes integer not null,        -- по умолчанию 60
    prompt_after_wake_minutes integer not null -- по умолчанию 60
);
```

Веса нормируются к сумме 1 при чтении. Если все три нуля — привычка считается ненастроенной и день не оценивается.

## 4. Модель оценки

### 4.1 Отклонения

Для ночи, приведённой к действующему часовому поясу цели (раздел 5):

```
devBed   = circular(bedMinutes,  goal.bedMinutes)
devWake  = circular(wakeMinutes, goal.wakeMinutes)
devSleep = max(0, goal.minSleepMinutes - asleepMinutes)

circular(a, b) = min(|a - b|, 1440 - |a - b|)
```

Отклонение времён круговое: отход в 23:50 при цели 00:10 — это 20 минут, а не 23 часа 40 минут.

Отклонение длительности **одностороннее**: пересып не штрафуется, цель сформулирована как «не менее».

`asleepMinutes` — сумма фактического сна внутри эпизода, а **не** разность подъёма и отхода. Это принципиально: лёг в 23:00, уснул в 02:00, встал в 07:00 даёт безупречные отход и подъём и штраф только по длительности.

### 4.2 Балл составляющей

```
s(d, m) = (1 + exp(-k * m)) / (1 + exp(k * (d - m)))
```

где `d` — отклонение в минутах, `m` — точка половинного балла, `k = 0.05` — крутизна, константа, не настраивается.

Свойства: `s(0, m) = 1` ровно; функция строго убывает; `s(m, m) = (1 + exp(-k*m)) / 2`.

При `m = 90` (времена):

| Отклонение, мин | 0 | 15 | 30 | 45 | 60 | 90 | 120 | 150 | 180 |
|---|---|---|---|---|---|---|---|---|---|
| Балл | 1.000 | 0.988 | 0.963 | 0.915 | 0.827 | 0.506 | 0.184 | 0.048 | 0.011 |

При `m = 60` (длительность):

| Недосып, мин | 0 | 15 | 30 | 45 | 60 | 90 | 120 |
|---|---|---|---|---|---|---|---|
| Балл | 1.000 | 0.950 | 0.858 | 0.713 | 0.525 | 0.192 | 0.050 |

Форма выбрана намеренно: малые отклонения почти бесплатны, средние стоят резко дорого, большие неразличимы между собой — два часа мимо и три часа мимо одинаково плохо.

### 4.3 Свёртка в процент

**Взвешенное геометрическое среднее** при нормированных весах:

```
score = sSleep^wSleep * sBed^wBed * sWake^wWake
value = round(score * 100 * 1000)   // с оговорками из 3.2
```

Геометрическое, а не арифметическое: одна сорванная составляющая должна тянуть весь результат вниз, а не компенсироваться двумя другими.

Контрольные примеры при цели «лечь 23:00, встать 07:00, спать ≥ 7:30» и весах 0.4 / 0.3 / 0.3 — они же служат тестовыми векторами:

| Ночь | sSleep | sBed | sWake | Доля | Процент |
|---|---|---|---|---|---|
| Лёг 23:10, встал 07:05, спал 7:55 | 1.0000 | 0.9929 | 0.9969 | 0.996939 | 100% |
| Лёг 23:41, встал 07:12, спал 6:48 | 0.7463 | 0.9308 | 0.9910 | 0.868280 | 87% |
| Лёг 00:00, встал 08:00, спал 8:00 | 1.0000 | 0.8267 | 0.8267 | 0.892062 | 89% |
| Лёг 01:00, встал 08:00, спал 7:00 | 0.8583 | 0.1845 | 0.8267 | 0.535074 | 54% |
| Лёг 02:00, встал 09:00, спал 7:00 | 0.8583 | 0.0111 | 0.1845 | 0.146865 | 15% |

Доля приведена с шестью знаками, потому что четвёртая строка стоит почти ровно на границе округления: 53.5074% округляется до 54, и проверка только целого процента была бы хрупкой. Тесты сверяются с долей, а процент проверяют дополнительно.

### 4.4 Разбор для экрана

Наряду с числом рассчитывается разбор: три пары «фактическое значение — балл» и признак того, какая составляющая внесла наибольшую потерю. Экран использует его для строки-объяснения.

## 5. Часовой пояс и плавный переход

Цель следует за местным временем, но не мгновенно: она догоняет новый пояс со скоростью `adaptation_minutes_per_day` (по умолчанию час в сутки), как адаптируется организм.

Действующий пояс цели — **не хранимое состояние, а чистая функция от истории**. Иначе результат зависел бы от того, когда пользователь открыл приложение, и история перестала бы пересчитываться.

```
observed[d] = utc_offset ночи дня d;
              при отсутствии — observed ближайшего более раннего дня с ночью;
              если таких нет — goal.homeUtcOffset

off[first] = goal.homeUtcOffset
off[d]     = off[d-1] + clamp(observed[d-1] - off[d-1], -rate, +rate)
```

Шаг задаётся наблюдением **предыдущего** дня, а не текущего. В ночь прилёта цель ещё не сдвинулась: организм за сутки не перестраивается, и первая ночь на новом месте оценивается по домашнему режиму. Со следующего дня цель начинает догонять.

Времена ночи приводятся к действующему поясу:

```
localMinutes(instantMillis, off) = ((instantMillis / 60000) + off) mod 1440
```

Пример, перелёт Москва (+180) → Нью-Йорк (−240), разница 7 часов, цель «лечь 23:00»:

| Суток после прилёта | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| Цель по местному времени | 16:00 | 17:00 | 18:00 | 19:00 | 20:00 | 21:00 | 22:00 | 23:00 |

Утреннее напоминание едет вместе с целью. Длительность сна поясом не затрагивается.

## 6. Пропуски

Записываются как `Entry.skip` на каждый день выбранного диапазона. Отдельной сущности «поездка» нет — диапазон существует только в интерфейсе.

- **Задним числом разрешено без ограничений.** Компенсируется тем, что на экране привычки постоянно висит счётчик «пропущено N из 30 дней» с датой последнего.
- Пропущенные дни исключаются из расчёта стабильности (иначе один перелёт раздувает разброс на две недели).
- Пропущенные дни не участвуют в подсказке цели по факту.

**Автоподсказка.** Если смещение ночи отличается от смещения предыдущей ночи на 120 минут и более, на экране появляется карточка с предложением отметить затронутые дни пропуском. Только предложение; ничего не применяется само.

## 7. Пропущенная ночь без пропуска

Порядок: утром приходит напоминание в момент «действующая цель подъёма + `prompt_after_wake_minutes`» с действиями «Ввести», «Пропуск», «Позже». Напоминание не приходит, если ночь уже есть.

Если до конца суток данных нет, день считается нулевым — потому что `Entry.unknown` уже даёт ноль в расчёте оценки.

**Синтетический ноль в базу не пишется никогда.** Благодаря этому поздняя выгрузка с часов или правка в Health лечит день задним числом, и серия восстанавливается. Записанный ноль такого бы не позволил.

## 8. Источники данных

### 8.1 iOS — свой плагин

`ios/Runner/HealthKitSleepPlugin.swift`, канал `org.isoron.uhabits/health_sleep`.

Ответственность плагина минимальна и намеренно лишена логики: запросить доступ, отдать сырые отрезки, принять запись. Вся обработка — в Dart, где её можно покрыть тестами.

Методы:

| Метод | Что делает |
|---|---|
| `authorizationStatus` | Текущее состояние доступа |
| `requestAuthorization` | Чтение и запись `HKCategoryTypeIdentifierSleepAnalysis` |
| `readSegments(fromMillis, toMillis)` | Отрезки за окно: начало, конец, вид, bundle id источника |
| `writeSession(startMillis, endMillis)` | Запись ручного ввода обратно в Health |
| `enableBackgroundDelivery` | `HKObserverQuery` + `enableBackgroundDelivery(.hourly)` |

Виды отрезков отображаются в `SleepSegmentKind`: `inBed`, `asleepCore`, `asleepDeep`, `asleepREM`, `asleepUnspecified`, `awake`.

В `Info.plist` добавляются `NSHealthShareUsageDescription` и `NSHealthUpdateUsageDescription`; в возможности цели — HealthKit с фоновой доставкой.

Отказ в доступе не является ошибкой: привычка продолжает работать на ручном вводе.

### 8.2 Android

Только ручной ввод. Health Connect в эту работу не входит. Экран и модель от платформы не зависят; при отсутствии источника блок автоматических данных не показывается.

### 8.3 Расписание сна Apple

**Недоступно программно ни на чтение, ни на запись.** В HealthKit единственный тип, связанный со сном, — `HKCategoryTypeIdentifierSleepAnalysis`, и это фактические данные. Целевые времена, заданные в приложении «Здоровье» или на часах, наружу не отдаются; будильники Clock тоже закрыты. Двусторонняя синхронизация расписания в эту фичу не входит, потому что невозможна.

Заменяется **подсказкой цели по факту** (раздел 10.4), которая даёт тот же практический эффект: расписание на часах меняет фактические данные, приложение это видит и предлагает подстроиться.

## 9. Склейка, дедупликация, привязка ко дню

Вход: сырые отрезки за окно. Выход: не более одного эпизода на логический день.

1. Отрезки группируются по bundle id источника. Выбирается группа с наибольшей суммой фактического сна. Так решается обычная ситуация, когда одну ночь пишут и часы, и стороннее приложение.
2. Внутри группы берутся отрезки сна (все виды `asleep*`). Отрезки, разделённые промежутком не более `merge_gap_minutes`, объединяются в цепочку. Выбирается цепочка с наибольшей суммой сна — это главный эпизод. Дневной сон остаётся за бортом.
3. `asleepMinutes` = сумма длительностей отрезков сна в цепочке, **не** размах цепочки.
4. Границы «в постели»: берутся отрезки `inBed`, пересекающиеся с цепочкой. Если они есть — `bedStart` это наименьшее начало, `wakeEnd` наибольший конец. Если их нет — берутся границы цепочки, и ночь помечается `derivedFromAsleep = 1`.
5. Логический день = календарная дата `wakeEnd` в смещении, действовавшем в этот момент.
6. Ручная запись за день **всегда** побеждает запись из Health.

**Настройка «сдвиг полуночи» на сон не распространяется.** У привычки со сном граница суток определяется пробуждением; применение к ней ещё и общего сдвига дало бы два разных понятия дня под одним именем.

## 10. Синхронизация и пересчёт

### 10.1 Когда

- при выходе приложения на передний план;
- по событию фоновой доставки HealthKit;
- по жесту обновления на экране привычки;
- после ручного ввода или правки цели.

### 10.2 Что

Перечитываются последние **14 дней**, а не только вчера — чтобы подхватывались поздние выгрузки с часов и правки в Health. Затем: склейка → сохранение ночей → пересчёт записей за эти дни.

Пересчёт идемпотентен: это чистая свёртка над ночами и целью, повторный прогон даёт тот же результат. Тест это фиксирует.

### 10.3 Пересчёт при смене цели

Изменение цели меняет проценты всех прошлых дней. Записи пересчитываются за всю историю привычки, а не только вперёд. Иначе история окажется смесью старой и новой шкалы — дефект, который не виден в тот день, когда цель меняли.

### 10.4 Подсказка цели по факту

Условие: за последние 14 дней есть не менее 10 ночей с данными; медиана отклонения отхода от цели не менее 30 минут; круговой разброс отхода не более 45 минут, то есть режим смещён устойчиво, а не разбросан.

Тогда показывается предложение сдвинуть цель к медиане. Только предложение. То же отдельно для подъёма.

## 11. Стабильность

За последние 14 дней, исключая пропуски и дни без данных:

- круговой разброс времени отхода;
- круговой разброс времени подъёма;
- средняя длительность сна.

Круговой разброс: `θ = 2π·m/1440`, `R = |среднее(e^{iθ})|`, разброс `= (1440 / 2π) · sqrt(-2 ln R)` минут. Обычное стандартное отклонение здесь непригодно: 23:50 и 00:10 отстоят на 20 минут, а не на 1420.

При числе пригодных ночей меньше 4 разброс не показывается.

## 12. Интерфейс

### 12.1 Список привычек

Ничего нового. Ячейка дня показывает процент — существующая числовая ячейка уже умеет числа и градацию цвета.

### 12.2 Экран привычки

Сверху четыре новых блока, ниже — существующие блоки приложения без изменений (оценка, история, серии, частота).

1. **Прошлая ночь.** Крупным числом процент ночи, рядом мелким — накопленная оценка и серия. Три карточки составляющих: фактическое значение и балл. Строка-объяснение словами, какая составляющая сняла балл.
2. **Ночи.** Дни слева направо, время сверху вниз, лента листается вбок — та же ориентация, что у всех остальных графиков приложения. Целевое окно — горизонтальная полоса. Пропуски показаны штриховкой, ночи ниже половины — предупреждающим цветом, последняя ночь выделена.
3. **Стабильность** за 14 ночей: разброс отхода, разброс подъёма, средняя длительность.
4. **Пропуски**: «пропущено N из 30 дней», дата последнего, переход к отметке диапазона.

### 12.3 Ручной ввод

Лист с двумя выборами времени — отход и подъём — и необязательным полем фактического сна. По умолчанию фактический сон равен разности. Сохранение пишет ночь с источником «вручную» и, при наличии разрешения, отправляет запись в Health.

### 12.4 Редактор привычки

Для типа «сон» вместо полей числовой привычки показываются: целевое время отхода, целевое время подъёма, минимум сна, домашний часовой пояс, скорость адаптации. Веса и точки половинного балла — в разделе для продвинутых, со значениями по умолчанию из 3.4.

## 14. Тестирование

- **Оценка.** Пять контрольных примеров из 4.3 как тестовые векторы. Отдельно: круговое отклонение через полночь; односторонность длительности; нормировка весов; вырожденный случай нулевых весов.
- **Границы служебных значений.** Ночь, дающая 0.003%, обязана записаться нулём, а не превратиться в пропуск. Тест обязателен — без него дефект молчалив.
- **Склейка.** Два источника на одну ночь; разрыв ровно на пороге и на минуту больше; дневной сон не побеждает ночной; отсутствие `inBed` поднимает `derivedFromAsleep`.
- **Часовой пояс.** Перелёт на 7 часов: проверяются все восемь дней таблицы из раздела 5. Обязательно **не** нулевое смещение: все существующие тесты напоминаний пинят `FixedTimeZone(0)`, а это единственное смещение, на котором ошибка приведения времени не проявляется.
- **Свёртка идемпотентна.** Двукратный прогон синхронизации над одними данными даёт одинаковые записи.
- **Пересчёт при смене цели** затрагивает всю историю, а не только будущее.
- **Стабильность.** Времена вокруг полуночи дают малый разброс, а не разброс в сутки.
- **Миграция.** База версии 25 поднимается до 100; существующие привычки не затронуты; повторный прогон безопасен.
- **Экран.** Виджет-тесты на четыре блока, включая случай «нет данных» и «нет разрешения Health».
- **Swift.** Оконная арифметика плагина в существующей цели `RunnerTests`.

Каждый тест цитирует идентификатор правила из `docs/extensions/SLEEP.md` в `reason:`.

## 15. Что не входит

- Health Connect на Android — только ручной ввод.
- Двусторонняя синхронизация расписания с Apple — невозможна, см. 8.3.
- Виджеты для привычки со сном — виджеты и так не читают общие данные, пока не заведена App Group.
- Фазы сна на экране — хранится только суммарная длительность.
- Цели по рабочему времени и прочий трекинг времени — следующая работа, отдельная спецификация.
- Настройка «сдвиг полуночи» для привычки со сном — сознательно не применяется, см. 9.
