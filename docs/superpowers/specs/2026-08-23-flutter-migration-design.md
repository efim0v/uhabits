# Миграция Loop Habit Tracker на Flutter — дизайн

**Дата:** 2026-08-23
**Статус:** утверждён
**Ветка:** `flutter-migration`
**Реестр паритета:** [`docs/parity/FEATURES.md`](../../parity/FEATURES.md) — 352 фичи, 3000 правил поведения

## 1. Задача

Форк Loop Habit Tracker — Android-приложение на Kotlin: `uhabits-core` (Kotlin
Multiplatform, ~180 файлов) и `uhabits-android` (~215 файлов), суммарно ~42k строк.
Нужно получить то же приложение на Flutter, работающее на iOS, Android и macOS, без
потери функционала, с сохранением текущего дизайна. Синхронизация между устройствами —
следующая фаза, здесь только подготовка данных под неё.

Успех = ноль неотмеченных пунктов в реестре паритета, приложение запускается и работает
на iPhone, Android и Mac.

## 2. Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Способ переноса | Полный перепис на Dart | KMP↔Flutter требует FFI-моста на каждый вызов; macOS и desktop через него поддерживать заметно дороже, чем портировать ~10k строк ядра |
| Место | Тот же репозиторий, `uhabits-flutter/` | Kotlin остаётся рядом эталоном: поведение сверяется, тесты гоняются рядом, откат возможен |
| Судьба Kotlin | Живёт до достижения паритета | Удаляется одним коммитом после финального аудита, не раньше |
| Старые данные | Совместимость не требуется | Личная база пользователя не мигрируется; схема проектируется чисто |
| Импорт/экспорт | Полный паритет, все 4 импортера | Loop DB, HabitBull CSV, Rewire DB, Tickmate DB — это фичи приложения, а не миграция данных; 30 из 33 io-фич уже покрыты Kotlin-тестами |
| Критерий «1:1» | Поведение строго, пиксели близко | Портированные тесты — жёсткий шлюз; графики проверяются golden-тестами и глазами против скриншотов Android |
| Локализации | Все языки одним скриптом | Конвертер `strings.xml` → ARB, разовая работа |
| Порядок | Скелет → ядро → вертикальные срезы | Риски платформы (подписи, права, sqflite на iOS, сборка macOS) вскрываются в первый день |
| Источник тестов | Реестр → красный Dart-тест → код | Kotlin не трогаем; для 103 непокрытых фич правила реестра и есть спецификация |
| Синхронизация | Фаза 2, отдельный спек | Здесь только подготовка схемы, сеть не трогаем |

## 3. Архитектура

```
uhabits/
├─ uhabits-core/                   Kotlin — эталон, не трогаем
├─ uhabits-android/                Kotlin — эталон, не трогаем
├─ docs/parity/FEATURES.md         реестр паритета (source of truth)
├─ docs/parity/DEVIATIONS.md       журнал осознанных отклонений от оригинала
└─ uhabits-flutter/
   ├─ packages/uhabits_core/       чистый Dart, БЕЗ зависимости от Flutter
   │   ├─ lib/src/models/          Habit, Entry, EntryList, Score, Streak, Frequency, ...
   │   ├─ lib/src/commands/        команды + CommandRunner + undo/redo
   │   ├─ lib/src/database/        репозитории, схема, миграции (интерфейс Database)
   │   ├─ lib/src/io/              импортеры, CSV-экспорт
   │   ├─ lib/src/preferences/     Preferences, WidgetPreferences (интерфейс Storage)
   │   ├─ lib/src/screens/**/      порт презентеров (ListHabitsBehavior и др.)
   │   ├─ lib/src/gui/             Canvas, Color, Theme — абстракции рисования
   │   └─ test/                    порт commonTest + тесты по правилам реестра
   └─ app/
       ├─ lib/ui/**                виджеты Flutter (экраны, карточки, диалоги)
       ├─ lib/platform/            FlutterCanvas, SqflitePlatformDatabase, файлы,
       │                           уведомления, шаринг — реализации интерфейсов ядра
       ├─ lib/l10n/                ARB-файлы всех локалей
       ├─ android/ ios/ macos/     нативные хвосты (виджеты, будильники, бэкап)
       ├─ test/                    виджет-тесты + golden
       └─ integration_test/        сквозные сценарии
```

### Ключевой инвариант

`packages/uhabits_core` не имеет права импортировать `package:flutter`. Проверяется
тестом в CI, который грепает исходники пакета. Следствия: тесты ядра бегут на `dart test`
за секунды без эмулятора; то же ядро позже переиспользуется в фоновом изоляте синка и в
CLI-утилите сверки паритета.

### Границы модулей

Ядро общается с платформой только через интерфейсы, объявленные в самом ядре:
`Database`, `Files`, `Storage` (preferences), `Canvas`, `NotificationTray`, `TaskRunner`.
Это ровно те же швы, что уже есть в Kotlin-версии, поэтому презентеры портируются без
перепроектирования. Реализации живут в `app/lib/platform/`.

### Состояние UI

Презентеры (`ListHabitsBehavior`, `ShowHabitMenuPresenter`, `HabitCardListCache` и
остальные) портируются один в один и оборачиваются в `ChangeNotifier`; проброс в дерево —
через `provider`. Никакого BLoC: логика уже разложена по behaviors, ломать её об чужую
архитектуру означало бы потерять построчную сверяемость с оригиналом.

## 4. Модель данных и заготовка под синхронизацию

Схема проектируется заново (обратная совместимость не требуется), но сразу с полями,
без которых синк пришлось бы переделывать:

- `uuid TEXT NOT NULL UNIQUE` у `habits` и `entries` — настоящий идентификатор; автоинкремент
  остаётся только внутренним ключом и никогда не покидает границу БД;
- `updated_at INTEGER NOT NULL` (unix ms) на каждой мутируемой строке;
- `deleted_at INTEGER` — удаление становится tombstone, физического DELETE нет;
- все мутации проходят только через команды, поэтому `updated_at` проставляется в одной
  точке (`CommandRunner`), а не в двадцати местах.

Сеть в фазе 1 не трогается вообще. В оригинале уже есть скрытые строки настроек
«Sync server / Sync key / Encryption key» (`settings.developer.sync-preference-rows`) —
они портируются как есть, скрытыми, и станут точкой входа фазы 2.

## 5. Порт рисования

В Kotlin-ядре графики нарисованы поверх собственной абстракции `platform/gui/Canvas` —
`HistoryChart`, `BarChart`, `Ring`, `StreakChart`, `FrequencyChart` не знают ничего про
Android. Абстракция портируется в `uhabits_core/lib/src/gui/canvas.dart`, реализация —
`FlutterCanvas` поверх `dart:ui`. Код рисования переносится построчно, а не переизобретается,
и остаётся покрытым портированными тестами (`BarChartTest`, `HistoryChartTest`, `CanvasTest`).

Эталон внешнего вида — существующие скриншоты
`uhabits-android/src/androidTest/assets/views/**/*.png`. Golden-тесты Flutter снимаются с
портированных виджетов и сверяются с ними глазами; попиксельное совпадение не требуется
(разные шрифтовые движки и антиалиасинг), совпадение композиции и цветов — требуется.

## 6. Цикл миграции

Единица работы — **слайс**: одна фича реестра со всеми её правилами.

| # | Шаг | Гейт перехода |
|---|---|---|
| 0 | Взять неотмеченную фичу из `docs/parity/FEATURES.md` | — |
| 1 | **RED** — каждое правило превращается в Dart-тест, цитирующий id правила | тесты написаны и падают |
| 2 | **GREEN** — порт кода из Kotlin, минимально до зелёного | — |
| 3 | **Прогон** — `dart test` + `flutter test` (вкл. golden) + запуск на симуляторе iPhone и на Android | всё зелёное на обеих платформах |
| 4 | **Аудит слайса** — сверить исходные Kotlin-файлы фичи с написанными тестами; всё неотражённое становится новыми пунктами реестра | аудит выполнен |
| 5 | Отметить галочку | ставится только если тесты зелёные И фича проверена вживую на обеих платформах |

**Определение готовности фичи.** Галочка `- [x]` означает одновременно: (а) каждое правило
фичи процитировано хотя бы одним проходящим Dart-тестом, (б) фича работает на iOS и на
Android, (в) отклонения от оригинала, если они были, записаны в `DEVIATIONS.md`.

**Выход из цикла.** Ноль неотмеченных пунктов И финальный сквозной аудит не порождает новых.
Пока аудит порождает пункты — цикл продолжается.

**Правило неисправления.** Реестр содержит правила, описывающие баги и инверсии имён
оригинала (например `models.entry-values#6`: числовое значение 3 неотличимо от SKIP;
`models.habit-list-ordering#8`; `charts-canvas-theming.color-model#7`). Порт воспроизводит
их. Исправление — продуктовое решение: оно допустимо, но требует записи в `DEVIATIONS.md`
с указанием id правила и причины.

## 8. Тестовая стратегия

| Уровень | Инструмент | Что покрывает |
|---|---|---|
| Ядро | `dart test` | Модели, скоринг, команды, репозитории, io, презентеры. Секунды, без эмулятора |
| Виджеты | `flutter test` | Экраны, карточки, диалоги, состояния |
| Графика | `flutter test` + golden | Все чарты и кнопки, эталон — скриншоты Android |
| Сквозные | `integration_test` | Сценарии, портированные из `uhabits-android/src/androidTest/.../acceptance` |
| Инвариант | тест в CI | `uhabits_core` не импортирует Flutter |
| Покрытие реестра | скрипт | Каждое правило реестра процитировано хотя бы одним тестом; непроцитированные — отчёт |

Единый вход `uhabits-flutter/test.sh` по образцу существующего `build.sh`. CI — GitHub
Actions: `dart test` и `flutter test` на каждый push, сборки iOS/Android/macOS на PR.

Скрипт покрытия реестра — не украшение: именно он механически отвечает на вопрос «весь ли
функционал мы принесли», потому что грепает id правил (`models.entry-values#4`) по
тестовым файлам и сравнивает со списком из `FEATURES.md`.

## 9. Высокорисковые элементы и решения по ним

64 фичи помечены `portRisk: high`. Политика по классам:

| Класс | Решение |
|---|---|
| Home-screen виджеты (17 фич) | Переписываются нативно: Android — Glance/RemoteViews через `home_widget`, iOS — SwiftUI/WidgetKit. Внешний вид сверяется с golden-эталонами Android. Волна W12 |
| Stack-widget (legacy) | Рендер сохраняется только на Android для существующих установок; на iOS не делается |
| Storage Access Framework (выбор папки, авто-бэкап, экспорт .db) | `file_picker` + `path_provider` + `share_plus`; на iOS «публичная папка бэкапов» — папка приложения в Files/iCloud Drive |
| Android Backup Agent | Остаётся тонким нативным хвостом на Android; на iOS эквивалента нет и не делается |
| Точные будильники, ребут, каналы уведомлений | `flutter_local_notifications`; Android — `RECEIVE_BOOT_COMPLETED` и exact-alarm gate, iOS — `UNCalendarNotificationTrigger` |
| Sticky-уведомления | Android — `ongoing: true`; на iOS эквивалента нет, фича становится Android-only, запись в `DEVIATIONS.md` |
| Bug report / logcat | `Runtime.exec("logcat")` заменяется на in-process кольцевой буфер логов в Dart |
| Конфетти (`konfetti`) | Своя реализация на Flutter |
| Интро (`AppIntro2`) | Ручной `PageView` с индикатором и кнопками Skip/Done |
| Радиальный time picker (вендоренный AOSP) | Обёртка над `showTimePicker` с добавленной кнопкой Clear. Точный циферблат AOSP не воспроизводится — осознанное отклонение, запись в `DEVIATIONS.md` |
| Границы суток и таймзоны | `DateTime.now()` + `timeZoneOffset`, плюс таймер полуночи и хук на возврат приложения из фона |

## 10. Вне области

- **Tasker/Locale-плагин** — Android-only интеграция, из паритета исключена по решению
  владельца проекта. Kotlin-код остаётся в `uhabits-android` до удаления модуля.
- **Синхронизация между устройствами** — фаза 2, отдельный спек. Здесь только поля схемы.
- **Изменение дизайна под iOS** — фаза 3. Порт сохраняет текущий внешний вид; переработка
  под платформенные гайдлайны начинается только после достижения паритета.
- **Исправление багов оригинала** — по умолчанию не делается, см. правило неисправления.
